Acceptance 1.0 Manual

让试点负责人照着完成完整闭环

本手册用于说明顶层战略 Agent 的完整使用路径：从登录账号，到完成从 0 到 1 构建，再到日常动态更新和专家评审。

01 登录与系统入口

登录验收演示账号

目的让新用户从账号登录开始进入系统，证明手册覆盖完整入口路径。
操作打开本地登录页，输入 local_owner@strategy-ai.local 和 owner123。
结果系统完成鉴权并进入仪表盘。

这一步证明：系统从登录账号开始，手册可指导新用户进入系统。

查看仪表盘与系统入口

目的帮助用户先看当前战略文档、构建进度和日更状态。
操作登录后进入仪表盘，查看文档卡片与更新时间线。
结果用户确认这不是问答工具，而是一套战略工作台。

这一步证明：用户进入后先看战略文档、构建进度和日更状态。

02 从 0 到 1 构建战略文档

进入从 0 到 1 构建入口

目的说明新战略文档可以从构建任务开始推进。
操作从侧边栏进入从 0 到 1 构建页面，选择验收演示构建任务。
结果系统进入逐层构建流程。

这一步证明：从 0 到 1 构建入口存在，可选择构建任务。

确认战略方向

目的证明 AI 会先拆出顶层战略方向，但需要用户判断。
操作查看方向卡片，对方向进行批准、拒绝或调整。
结果确认后的方向进入下一层维度拆解。

这一步证明：AI 拆解战略方向后，用户进入逐层确认流程。

确认战略维度

目的证明每个战略方向可继续拆成可管理维度。
操作逐条查看维度定义和重要性，进行批准、拒绝或调整。
结果系统保留人的判断，并推进到观点层。

这一步证明：用户可确认战略维度，AI 不直接替人拍板。

确认具体观点与来源

目的证明战略内容可落到可追溯观点，而不是停留在宽泛方向。
操作查看正式文档中的观点、原始引用、会议名称和来源日期。
结果观点进入战略文档后仍保留追溯依据。

这一步证明：构建完成后，观点进入正式战略文档，并保留来源引用以支持追溯。

完成战略文档发布

目的证明从 0 到 1 构建闭环能够到达完成态。
操作查看完成态战略文档和构建记录。
结果战略文档形成可追溯正式版本。

这一步证明：从 0 到 1 构建闭环可到达完成态。

03 日常动态更新

进入日常动态更新

目的说明系统可持续接收新会议和外部变化。
操作进入日常更新页面，查看今日更新任务。
结果用户看到待处理或已完成的动态更新任务。

这一步证明：日常动态更新入口和任务列表存在。

审核变更建议

目的证明系统能把新信息转化成可判断的变更建议。
操作查看修改、新增或删除建议，选择采纳、拒绝或调整。
结果AI 给建议，人做判断。

这一步证明：系统生成变更建议，用户可采纳、拒绝或调整。

进入日更专家复核

目的证明日常变更也能经过专家复核。
操作进入专家复核页，查看专家对变更建议的讨论。
结果变更建议获得更稳健的判断依据。

这一步证明：日更变更进入专家复核。

完成日更决策闭环

目的证明日常更新最终回写战略文档，而不是停留在提示层。
操作查看最终决策页，确认采纳范围和完成结果。
结果战略文档进入新版本，后续继续追踪影响。

这一步证明：日更最终由人做决策并形成闭环。

04 专家评审与最终判断

查看专家评审

目的证明系统不是 AI 单点决策，而有多专家审阅。
操作进入专家评审页面，查看专家讨论、争议点和建议。
结果负责人基于专家意见做最终判断。

这一步证明：战略文档进入专家评审，人保留最终判断。

05 术语库、权限与系统辅助能力

理解系统地图

目的帮助试点负责人理解仪表盘、文档、构建、日更和专家评审之间的关系。
操作从左侧导航依次进入核心模块，确认每个模块承担的任务。
结果用户知道复杂系统的主路径，不需要在菜单中盲找功能。

这一步证明：仪表盘和导航结构提供系统地图。
